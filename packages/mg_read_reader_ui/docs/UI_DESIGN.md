# 0.4.0 UI 设计规范

本文定义 `novel_reader_ui` 0.4.0 的内部视觉系统、响应式规则和人工验收基线。视觉目标是安静、
清晰、适合长时间阅读，而不是复刻任何商业阅读应用。宿主不能通过颜色、圆角、字体或 Widget
Builder 改写首版视觉。

## 1. 设计原则

- **阅读优先**：正文永远是最高层级，工具栏、页脚和提示保持低干扰。
- **原创克制**：可借鉴通用阅读交互，但不复制品牌图标、字体、插画、纹理或专有布局。
- **稳定优先**：异步内容和工具栏显隐不得改变正文可用尺寸、分页边界或语义位置。
- **少而一致**：统一使用少量间距、圆角、字体层级和图标风格，避免大而笨重的卡片与重复入口。
- **能力诚实**：未注册评论、章节状态、外部字体或平台能力时，隐藏对应 UI，不展示无效开关。
- **可恢复**：局部失败保留已成功内容，给出紧邻问题位置的重试，不用全屏错误覆盖可读正文。

## 2. 视觉 token

所有数值集中在视觉 token 文件中，Widget 不散落魔法值。当前基线如下；调整时应整体评估，
不能只修单一页面。

### 2.1 间距与尺寸

| 类别 | 基线 |
| --- | --- |
| 微间距 | 4dp、8dp |
| 控件内间距 | 10dp、12dp、14dp |
| 内容边距 | 14dp～20dp |
| 区块间距 | 16dp、20dp、24dp、28dp |
| 最小触控/鼠标目标 | 48 × 48dp |
| 设置行与主要控件高度 | 48dp |
| 设置标签列 | 52dp |
| 设置色点 | 36dp 视觉尺寸，外层仍为 48dp 目标 |
| 背景缩略图 | 76 × 40dp，外层仍满足 48dp 目标 |
| 设置底部导航 | 68dp |
| 设置内容最大宽度 | 520dp |
| 设置面板最大宽度 | 720dp |
| 桌面设置面板最大高度 | 560dp |

视觉元素可以小于 48dp，但其命中区域、键盘焦点和语义节点不得小于 48dp。紧凑不等于牺牲
可访问性。

### 2.2 圆角与边界

- 小型控件与缩略图：9dp。
- 提示、列表选中态和普通卡片：12～14dp。
- 胶囊控制：18dp。
- 底部面板顶部圆角：20dp。
- 选中描边：2dp；普通分隔线采用低对比 1px 视觉线。

同一层级不得混用大量不同圆角。面板以表面色、细分隔或极轻阴影建立层次，不使用厚重投影和
多重边框。

### 2.3 字体与图标

- 正文大小由阅读设置控制，标题、标签、页脚和提示采用有限的固定层级。
- 标题最多使用中等或半粗字重；正文不使用大面积粗体。
- 图标采用同一套 Material 轮廓/圆角语汇，同一动作只保留一个入口和一个含义。
- 所有图标按钮提供简体中文 tooltip 与语义标签；重要状态不能只依赖颜色或图形。
- 默认内置字体和平台回退链必须离线可用；外部字体失败时视觉无跳崩并回退默认字体。
- 外部字体条目来自 `ReaderFontRepository.loadCatalog()`；安装、预览和移除状态均局限在字体子页，
  不能以全屏进度阻挡已加载正文。

## 3. 色彩、背景与亮度

七套阅读配色分别提供背景、正文、次级文字、面板、分隔线和强调色：日间、护眼、羊皮纸、
雾蓝、夜间、深夜和炭灰。六套原创背景作为正文下方独立绘制层，不改变正文布局。

明暗主题遵循以下规则：

- 浅色正文不用纯黑，深色正文不用纯白；保持舒适对比而非极端对比。
- 深色背景素材自动降低饱和度与透明度，面板与正文背景保持可辨但不过度悬浮。
- 强调色用于选中、焦点和主要动作，不大面积铺满阅读页。
- 亮度由阅读区域的黑色遮罩实现，不修改设备全局亮度。
- 亮度遮罩位于正文和背景之上、工具栏/面板/提示之下，不能降低控件可读性。
- loading、空、错误和选中状态在每套配色下都需具备文字或图标冗余表达。

## 4. 响应式布局

### 4.1 360dp 窄屏

- 面板近全宽，保留安全区和 14dp 左右内容边距。
- 设置使用 52dp 紧凑标签列，右侧控件弹性占满；无法并排的内容换行或横向滚动，不能压缩到
  小于 48dp 命中区域。
- 正文工具栏标题使用弹性宽度和单行省略，左右动作不能挤出屏幕。
- 底栏四个主要入口等分；图标和短标签垂直排列，不叠字、不裁切。
- 书籍预览、评论和目录列表使用单列；主要按钮不超过内容宽度，说明文字允许自然换行。

### 4.2 520dp 中间宽度

520dp 是紧凑布局断点。达到该宽度后可以增加内容留白或让部分控件稳定并排，但不得突然改变
导航语义、操作顺序或滚动位置。面板仍以内容为中心，不将手机控件机械拉伸到全宽。

### 4.3 720dp 宽窗口

- 设置面板最大宽度 720dp，内部内容最大宽度 520dp 并居中。
- 评论、目录和书签面板使用各自受控最大宽度，周围显示遮罩而非无限拉伸列表。
- 正文保持舒适行长和页边距，不因窗口变宽形成横跨全屏的长行。
- 桌面窗口高度不足时内容区域独立滚动，固定标题/标签和底部导航不互相覆盖。
- 鼠标悬停、键盘焦点和滚轮行为需要可见反馈，不能只为触屏设计。

所有宽度都需检查竖屏、横屏和窗口连续缩放。布局断点改变后通过语义锚点恢复，不保留失效的
页码或像素偏移。

## 5. 文字缩放与可访问性

阅读器将系统文字缩放与用户字号明确合并，并把内部工具 UI 的有效缩放上限控制为 1.3。人工
验收必须在 1.0 和 1.3 两档执行。达到 1.3 时：

- 标题、按钮、标签、计数和错误文案不裁切、不重叠。
- 单行标题允许省略，业务说明和错误原因允许换行，不能用缩小字体掩盖溢出。
- 控件高度可按需增长，但命中区域始终至少 48dp。
- 正文重排后恢复相同 `chapterId + paragraphId + characterOffset`。
- 键盘焦点顺序与视觉顺序一致；焦点、选中和禁用状态都有非颜色提示。

正文最小字号和最大字号由设置模型集中约束。不得关闭系统语义，也不得因缩放隐藏必要操作。

## 6. 页面结构

### 6.1 书籍预览

书籍封面式占位、标题、作者、简介、评论摘要和开始阅读形成单一纵向层级。内容最大宽度受控，
窄屏可滚动。开始阅读是唯一强调按钮；目录、评论等次级入口不与其竞争。

### 6.2 正文 chrome

- 顶栏仅保留返回、章节标题、书签和必要刷新，避免同一功能同时出现在菜单与底栏。
- 来源/章节链接是低干扰信息条，仅在有效且可操作时显示。
- 工具栏覆盖在固定正文区域上，显隐不能引发重排。
- 底部先显示上一章、全书进度和下一章，再显示目录、夜间、设置和书签四个等分入口。
- 页脚中的页码、全书进度和时间使用次级文字，不与正文争夺注意力。

### 6.3 目录、书籍详情与书签

三标签底部面板共享相同标题高度、圆角、拖动把手和安全区。目录当前章同时通过背景、文字权重
和语义选中态表达；空目录、空书签和加载更多使用局部状态。删除书签采用明确 tooltip，不能让
删除图标与进入操作混淆。

目录初始状态来自 `ReaderChapterInfo`，注册 `ReaderChapterStateCapability` 后可用
`ReaderChapterState` 刷新。远程书籍可在目录尾部显示已下载、未下载、下载中、失败或未知状态；
本地来源不展示无意义的下载动作，未注册 capability 时只使用目录已有快照，不制造下载进度。
已读状态不能只用浅色表达，下载中不能挤压章节标题或改变行高。进入章节后调用 `markRead` 的
宿主失败仅显示低干扰局部提示，不把正文切回未读位置。

### 6.4 设置

设置主面板顺序固定为亮度/护眼、字号/字体、七个配色色点、六个背景缩略图、翻页方式、间距/
评论/更多入口和自动阅读。字体、间距、评论与更多作为子页，返回后保持主面板滚动语义。

Android 面板约占可用高度的 82%，近全宽；宽窗口受 720 × 560dp 上限约束。内容区可滚动，
底部导航固定。亮度拖动实时预览，结束或关闭面板时持久化一次。

字体子页先展示内置字体，再展示 `ReaderFontDescriptor` 目录。未安装项的主要动作是安装，已
安装项可选择或移除；预览字节缺失时使用文字样张，不显示破图。选择结果写入
`TextReaderPreferences.customFontId`，恢复内置字体时使用
`copyWith(clearCustomFontId: true)`。安装失败保留条目和重试入口，当前正文继续使用上一款
有效字体。

## 7. 段落评论的行内契约

段评气泡是段落末尾的行内尾随元素，视觉上紧随最后一个正文字符：当前行剩余空间足够时与最后
文字同行；不足时作为同一段落的下一行首个元素，而不是独立大卡片或评论正文摘要。

为避免异步评论破坏分页：

- 分页首次测量就为气泡预留固定宽高，数量变化只替换内部内容。
- loading、`0`、成功计数和错误均使用同一几何；大计数使用固定规则缩写或省略。
- 气泡只显示评论图标与数量，不显示作者、头像或评论正文。
- 行内占位在首次测量时固定为 48 × 48dp，同时作为完整点击目标；内部视觉气泡为 30 × 30dp。
  这块固定占位会参与初次换行与分页，但 loading、数量和错误等异步状态不得再改变其几何。
- 未注册评论 feed 时不预留气泡；注册后即使零评论也显示 `0`。
- 横向分页不得把气泡重复绘制到相邻页；纵向恢复仍以段落 ID 和字符偏移为准。

点击气泡打开当前段落的只读评论列表。列表中的加载、空、错误、重试和分页都是局部状态，关闭
后返回原语义位置。

## 8. 加载、空、错误与提示

### 加载

首次加载使用尺寸克制的进度指示和简短文案。已存在正文或列表时，刷新只显示局部进度，不用
全屏遮罩。漫画图片使用固定纵横比骨架；字体下载状态由宿主仓库提供，插件不伪造进度。

### 空状态

空目录、空书签、零评论和空章节必须区分。空状态使用一个低对比轮廓图标和一句可行动文案，
不使用巨大插画。零评论仍保留可进入的只读入口；未注册评论能力则完全隐藏入口。

### 错误

错误显示在失败所属区域，包含简洁原因和至少 48dp 的重试目标。已有正文、已解码漫画页或内置
字体不能因相邻资源失败而消失。重复失败通知观察器，但 UI 不展示原始堆栈或敏感信息。

### 短提示

“没有下一章”、保存失败等短提示采用小圆角、高对比但非纯黑的浮层，避开系统安全区和固定
导航。提示自动消失不能阻塞键盘或阅读手势，重要错误仍需可重试的持久局部状态。

## 9. 动效与减少动态效果

正常模式下仅使用短、可解释的过渡：设置状态约 160ms，面板约 220ms。仿真、覆盖和平移只
作用于已分页页面的视觉层，不改变分页边界。

当系统要求减少动态效果时：

- 横向翻页统一降级为无动画跳转。
- 面板和设置切换移除位移、缩放、透视与大面积淡入，只保留必要的瞬时状态变化。
- 自动阅读仍可运行，但不能依赖装饰动画表达正在运行；必须有文字或图标状态。
- loading 指示避免强烈闪烁，漫画渐进加载不做反复放大或脉冲。

动画期间手动翻页、滚动、打开面板、进入后台或销毁组件时，相关 Controller、Timer 和 Ticker
必须停止并释放。

## 10. Comic 纵向阅读视觉

- 每张漫画页在字节到达前使用已知纵横比固定占位，不能以零高度插入。
- 完整图片字节返回后保持相同页面边界；解码失败在页内显示重试，不移除前后已成功页面。
- 相邻章节用低干扰章节分隔标识衔接，下一章加载失败时停留在当前章末页而非空白区域。
- 纵向滚动只挂载视口附近页面；回收远端页面后仍按 `ComicImageInfo` 稳定 ID 与归一化页内
  `imageFraction` 恢复 `ComicReaderProgress`。
- 图片背景、工具栏和系统栏在明暗主题下保持可辨，不能通过给漫画本身套阅读亮度滤镜改变作品。
- 目录、进度和书签使用 `ComicChapterInfo`、`ComicReaderProgress`、
  `ComicReaderBookmark` 与 `ComicReaderPreferences` 的独立语义，不显示文本段落或字符偏移
  术语；UI 命令和只读状态分别经 `ComicReaderController` 与 `ComicReaderSnapshot` 暴露。
- 单图只读评论使用 `ReaderCommentTarget.comicImage` 绑定对应 `ComicImageInfo`，入口叠放在
  已确定尺寸的图片层上；不得因评论摘要返回而改变图片占位高度。未注入 comment feed 时不
  显示入口或预留空间。

## 11. 人工验收矩阵

本仓库不使用 Widget、Golden 或集成测试；重大视觉修改经授权后使用 `example/` 人工检查。
每次视觉验收至少覆盖下表：

| 维度 | 检查项 |
| --- | --- |
| 宽度 | 360、520、720dp；竖屏、横屏、连续窗口缩放 |
| 文字 | 1.0 与 1.3 缩放；长标题、长作者、长错误文案、大评论数 |
| 配色 | 七套配色，重点检查日间、护眼、夜间、深夜 |
| 背景 | 六套背景的正文对比、缩略图一致性和深色降饱和 |
| 状态 | 首次 loading、局部 loading、empty、error、retry、短 notice |
| 导航 | 点击分区、拖页、滚动、跨章、目录跳转、书签跳转、末章 |
| 设置 | 亮度、护眼、字号、字体、背景、间距、四种动画、纵向、恢复 |
| 章节状态 | 本地/远程/未知来源；下载五态、已读、刷新失败和无 capability |
| 外部字体 | 目录、缓存预览、安装、选择、移除、摘要不符、失败回退和清除选择 |
| 评论 | 书籍/章节摘要、段评同行、0、加载、错误、分页、热度/最新 |
| 自动阅读 | 三档速度、跨章、手动停止、后台停止、末章停止、销毁释放 |
| 可访问性 | 48dp 命中、tooltip、语义标签、键盘焦点、减少动态效果 |
| Comic | 固定占位、逐图调度、失败重试、反向滚动、跨章和独立书签 |

### Android

在现有 Android 模拟器可进行点击、拖动、旋转和截图人工复核；最终仍需真机检查系统返回、
常亮、前后台、触控手势和内存压力。模拟器检查只能称为“人工交互检查”。

### Windows

必须在 Windows 主机或对应 CI/真机检查鼠标拖页、滚轮、键盘快捷键、窗口缩放、焦点和常亮。
在 macOS 上不能声称 Windows 编译或运行通过。

### macOS 本轮限制

macOS 本轮只作为 Flutter UI 人工观察与源码/静态分析环境，不属于交付支持平台。macOS 截图
不能替代 Android 的系统交互和 Windows 的桌面输入验证，也不能证明 macOS 原生能力可用。
交付说明必须列出未执行的真机、平台构建和原生行为项。

## 12. 视觉交付检查

- 页面层级清晰，没有大而空、比例失衡、重复入口或廉价装饰图标。
- 所有页面共享 token、圆角、留白、图标和文字层级，明暗主题一致。
- 360/520/720dp 和 1.3 文字缩放无溢出，所有操作目标至少 48dp。
- 工具栏、异步评论、图片和字体状态不改变当前语义位置。
- loading、empty、error、retry 和减少动态效果均有真实可达状态。
- 视觉素材原创或许可明确，外部字体与漫画内容的归属由宿主保留。
- 人工检查结果准确描述为人工验收，不把静态分析或截图表述为自动化测试通过。
