# AGENTS.md

本文件是 `novel_reader_ui` 仓库的长期开发契约。所有开发者与自动化 Agent 在修改本仓库前都必须完整阅读并遵守本文件。若临时需求与本文件冲突，应先更新本文件并说明原因，再修改实现；不要让代码和文档长期处于互相矛盾的状态。

## 1. 项目定位

`novel_reader_ui` 是供更大 Flutter 应用嵌入的文本与漫画阅读器插件，不是内容平台 App。

它负责：

- 小说正文的排版、分页、滚动和章节导航。
- 阅读页内部的工具栏、目录、书签、主题与排版设置 UI。
- 可选的书籍、章节和段落三级只读评论浏览入口。
- 阅读会话、前后台生命周期和屏幕常亮管理。
- Android 与 Windows 所需的原生能力。
- 纵向漫画的逐图渐进加载、章节衔接和独立语义状态。
- 对宿主暴露稳定、异步、可替换的业务接口。

它不负责：

- 书架、书城、推荐、搜索、独立书籍详情页和排行榜；阅读器内仍可展示当前书籍的轻量详情。
- 登录、账号、会员、付费、广告、内容审核和 DRM。
- 网络协议、鉴权、数据库、云同步或宿主路由。
- 小说、漫画图片或外部字体的下载、许可判断与持久缓存。
- TXT/EPUB 文件解析、听书和划线笔记。
- 评论发布、回复、点赞、举报、许愿改编或其他平台运营交互。

阅读结构可以参考番茄阅读、起点等成熟产品的通用交互，但不得复制其品牌名称、图标、插画、专有布局细节或其他受保护素材。组件应形成独立、克制、适合长时间阅读的视觉语言。

## 2. 当前目标和平台优先级

目标交付形态是一个 Flutter plugin package：

1. Android 是第一优先平台，必须先完成真实设备验证。
2. Windows 是第二优先平台，必须支持键盘、鼠标和可变窗口尺寸。
3. iOS、macOS、Linux 和 Web 暂不属于承诺支持范围；不得为了它们破坏 Android/Windows 的清晰实现。本轮仅授权在 macOS 进行 UI 人工验收，不代表新增平台支持。
4. 根包是插件本体，`example/` 是唯一演示应用。不要在根 `lib/main.dart` 维护第二套 App。
5. 包名保持 `novel_reader_ui`。公共 Dart 入口固定为 `lib/novel_reader_ui.dart`。

注意：Windows 构建只能在 Windows 主机或对应 CI 环境中完成。在 macOS/Linux 上不得声称已完成 Windows 编译验证；应明确记录未执行原因，并通过 Windows CI 或真机补验。

## 3. 目标目录结构

新增代码应遵循以下边界，避免把所有实现堆入单文件：

```text
lib/
  novel_reader_ui.dart           # 唯一公共导出入口
  src/
    api/                          # 公共模型、接口、控制器契约
    core/                         # 与 UI 无关的会话、缓存、错误、生命周期逻辑
    pagination/                   # 纯文本分页、位置映射和布局缓存
    platform/                     # Dart 侧平台通道与常亮协调器
    ui/                           # 阅读页、面板、主题、组件
android/                          # Kotlin 插件实现
windows/                          # C++ 插件实现
example/                          # Android/Windows 演示宿主
```

仅 `lib/novel_reader_ui.dart` 导出的符号属于公共 API。`lib/src/` 中未被该入口导出的内容均视为私有实现，示例不得通过深层路径依赖。

## 4. 架构原则

采用以下单向依赖：

```text
宿主实现的数据/状态接口
          ↓
公开 API 与不可变模型
          ↓
阅读会话控制器与运行时
       ↙      ↘
文本分页内核   Flutter UI
          ↓
平台能力抽象 → Android / Windows
```

强制规则：

- UI 不直接访问网络、数据库、文件系统或宿主 Service Locator。
- 分页内核不得依赖具体 Widget、BuildContext、平台通道或宿主实现。
- 原生平台通道不得承载书籍、章节和阅读设置等业务数据。
- 宿主回调失败不能导致阅读页崩溃；错误应归一化并交给观察器。
- 不在 `build()` 中发起业务请求、写入持久化状态或获取原生资源。
- 不引入全局单例保存当前书籍、进度或主题。屏幕常亮协调器可以是进程级共享资源，但必须引用计数并支持替换平台实现。
- 不使用根 `Navigator`、全局路由表或假定宿主的状态管理方案。
- 优先使用 Flutter/Dart 标准能力。新增第三方依赖前必须说明必要性、平台支持、维护状态和体积影响。

## 5. 公共 API 契约

### 5.1 主组件

主入口组件命名为 `TextReaderView`，构造参数只允许包含业务接入项：

- 必需的 `bookId`。
- 必需的 `TextReaderDataSource`。
- 必需的 `TextReaderStateStore`。
- 可选的 `ReaderObserver`。
- 可选的 `TextReaderController`。
- 可选的扩展能力注册对象。

不得开放颜色、字体、圆角、间距或任意 Widget Builder 给宿主来改变首版视觉。主题和排版选项属于阅读器自身设置系统，由组件内部 UI 修改，由宿主接口持久化。

组件不自行 `Navigator.pop`。返回按钮、Escape 和系统返回键统一触发 `ReaderObserver.onExitRequested`；宿主决定关闭页面、弹窗确认或执行其他路由行为。

### 5.2 异步数据源

`TextReaderDataSource` 的所有业务读取方法必须返回 `Future`：

- `loadBookInfo(bookId)`：加载轻量书籍信息。
- `loadChapterCatalog(...)`：使用游标分页加载章节元数据，响应必须包含条目、下一游标、总数及 `hasMore`。
- `loadChapterAtIndex(bookId, index)`：按全书顺序索引直接定位单个章节元数据，供全书进度跳转使用；不得为跳转顺序扫描全部目录页。
- `loadChapterContent(bookId, chapterId)`：加载单章正文。

数据源不得返回 Widget、TextSpan、数据库实体或 HTTP Response。异常可以向上抛出，运行时负责转换为可恢复的 `ReaderFailure`。

目录条目必须有稳定 `chapterId`、标题和顺序索引。章节正文必须有稳定 `chapterId`，且段落顺序在同一内容版本内保持一致。

### 5.3 正文模型

文本正文使用结构化纯文本：

- `TextChapterContent` 表示一章。
- `TextParagraph` 至少包含稳定 `id` 和纯文本 `text`。
- 不接受 HTML 作为核心正文格式。
- 空段落应被规范化，但不得静默合并具有不同 ID 的段落。
- 段落 ID 是阅读位置、书签和段落评论的稳定锚点。

富文本、插图或脚注属于未来显式扩展，不得以大量 `dynamic` 字段提前污染首版模型。

`ReaderBookInfo.sourceKind` 只描述本地、远程或未知来源。`ReaderChapterInfo` 可附带下载状态、字数和已读状态，旧构造调用必须继续使用安全默认。进入未下载章节仍调用 `loadChapterContent`；宿主可在该 Future 中完成下载与缓存，插件不得直接联网。动态状态由可选 `ReaderChapterStateCapability.loadChapterStates` 批量刷新，已读通知使用幂等 `markRead`。

### 5.4 状态存储

`TextReaderStateStore` 由宿主实现，所有读写均为异步：

- 读取/保存 `ReaderProgress`。
- 读取/保存 `TextReaderPreferences`。
- 读取、添加和删除 `ReaderBookmark`。

插件不得内置数据库，也不得假定用户 ID、账号体系或同步策略。宿主实现可通过闭包或对象内部状态捕获当前用户上下文。

`ReaderProgress` 必须使用语义位置：`chapterId + paragraphId + characterOffset`，并携带可展示的章节/全书进度信息。书籍信息预览使用明确的 `chapterIndex = -1` 状态，不伪造成正文段落。页码和像素滚动偏移只能作为临时 UI 状态，不能作为唯一持久化位置，因为窗口尺寸或字体变化会使其失效。

`ReaderBookmark` 同样保存语义位置。书签标题、摘要和创建时间由插件生成后交给宿主保存。

### 5.5 设置模型

`TextReaderPreferences` 至少包含：

- `ReaderThemePreset`：日间、护眼、羊皮纸、夜间、雾蓝、深夜和炭灰七套配色。
- `ReaderBackgroundPreset`：六套由插件提供的原创阅读背景；不得复用参考产品的插画、纹理或其他受保护素材。
- `ReaderFontPreset`：系统默认、无衬线、衬线。
- 字号、行高、段间距和水平页边距。
- `ReaderNavigationMode`：横向分页或纵向滚动。
- 页面亮度遮罩比例。
- 是否在阅读期间保持屏幕常亮。
- 横向分页动画：纯 Flutter 实现的仿真、覆盖、平移或关闭动画；不得引入原生卷页视图或改变正文分页语义。

设置值必须有集中定义的合法范围和默认值。读取到越界或未知值时使用最近合法值或默认值，不能导致布局异常。宿主只负责原样持久化和回传，不负责生成组件样式。

自动阅读是阅读器会话级状态，不属于 `TextReaderPreferences`，不得由宿主持久化为跨会话默认行为。

外部字体使用可空 `customFontId` 持久化，空白值回退内置字体。字体目录、许可、下载、完整性校验、预览与缓存全部由 `ReaderFontRepository` 承担；插件只消费宿主提供的字节，不请求 descriptor URL。Flutter engine 已注册字体在进程内不可卸载，删除只清理宿主缓存并影响后续加载。

### 5.6 控制器和观察器

`TextReaderController` 是可选的命令入口，应支持：

- 打开指定章节。
- 上一页、下一页。
- 上一章、下一章。
- 显示、隐藏或切换工具栏。
- 刷新当前章节。
- 启动、停止或切换会话级自动阅读。
- 暴露只读、可监听的 `TextReaderSnapshot`，其中包含自动阅读运行状态。

控制器在未绑定、已销毁或命令暂不可执行时必须安全失败，不能访问陈旧 State。

`ReaderObserver` 应接收：

- 会话进入和退出。
- 标准化生命周期变化。
- 当前章节变化。
- 可恢复错误。
- 用户退出请求。

观察器用于通知，不负责驱动阅读器内部状态机。不要让宿主必须实现所有回调；提供空实现或默认适配器。

## 6. 评论扩展边界

评论采用可选、只读的独立扩展能力：

- 保留 `bookId`、`chapterId`、`paragraphId` 或 `imageId` 组成的稳定评论目标类型。
- 支持书籍、章节、文本段落和漫画图片评论目标；评论读取方法必须异步，并使用只读、不可变的展示模型。
- 扩展注册采用可选 capability，不得向核心数据源或状态存储强加评论方法。
- 未注册评论能力时，阅读 UI 不显示空入口或占位计数。
- 已注册能力时，通过独立 UI 展示只读评论列表，并处理 loading、empty、error 和 retry；评论加载失败不得阻断正文阅读。
- 书籍和章节入口展示评论总数与只读摘要；段落入口只展示数量，不展示评论正文摘要。段评气泡必须紧随该段最后一个字同行显示，评论数量直接显示在气泡内部，即使为零也显示 `0`；点击气泡打开该段落的只读评论列表。
- 段落评论气泡在 loading、零评论、成功和错误状态下占用相同的行内预留空间。异步评论数量到达或变化时只能更新气泡内部状态，不得触发正文重排、分页边界变化或阅读位置跳动。
- 评论入口和列表不得修改正文段落身份规则，也不得影响分页缓存、阅读位置或书签语义。
- 不实现评论发布、回复、点赞、举报、许愿改编或其他写入/运营能力，不为这些能力预留易变化的完整模型。

## 7. 阅读会话与异步规则

### 7.1 初始化

首次进入时并行读取书籍信息、首批目录、已保存进度和阅读设置。没有已保存正文进度时默认进入 `chapterIndex = -1` 的书籍信息预览，不预加载或排版整本书；只有进入目标章节、设置和可用视口均就绪后才执行该章分页。

初始化失败必须显示阅读器自己的错误状态和重试操作。已成功的数据可以复用；重试不得无条件重复所有请求。

### 7.2 请求竞态

- 每次章节切换或刷新使用递增请求世代或等价取消策略。
- 过期请求完成后不得覆盖较新的章节、进度、错误或 loading 状态。
- 快速连续翻章时同一章节请求应去重。
- dispose 后所有异步完成回调必须变为无操作。
- 不依赖 `Future` 完成顺序表达用户意图。

### 7.3 缓存

- 组件只负责会话级内存缓存；持久缓存属于宿主。
- 正文只缓存当前章和下一章；分页结果只保留当前章。
- 下一章允许后台预取正文，但不得提前排版。
- 上一章不常驻缓存。用户返回上一章时临时重新加载和排版，并直接定位末页；此时原当前章自然成为新当前章的下一章，从而形成无缝衔接。
- 分页缓存键至少包含章节内容身份、可用尺寸和全部影响排版的设置。
- 切换设置或窗口大小时只失效相关分页缓存，目录和正文缓存不得一并清空。
- 缓存必须有明确上限，不得随阅读章节数无限增长。

### 7.4 保存策略

- 阅读位置稳定变化后约 800ms 防抖保存。
- 换章、加入/删除书签、修改设置、进入后台、收到退出请求和组件销毁时立即提交最新快照。
- 生命周期回调不能等待宿主慢 I/O 才释放原生常亮资源。
- 保存失败不阻断阅读；通过观察器报告，并在下一个保存检查点再次尝试。
- 相同快照不得重复高频写入。

### 7.5 自动阅读

- 自动阅读只在当前阅读会话内运行，不写入宿主状态存储；重新进入阅读器时默认关闭。
- 横向模式按稳定节奏前进页面，纵向模式按稳定速度滚动；章节边界继续沿用正常的相邻章节加载和错误处理路径。
- 用户手动翻页或滚动、进入后台、发生加载错误、到达全书末尾、收到退出请求或组件销毁时立即停止自动阅读。
- 自动阅读使用的 `Timer`、Ticker、ScrollController 或监听器必须成对释放，不能在 dispose 后继续驱动 UI。

## 8. 分页和位置恢复

横向模式使用确定性的文本测量分页服务：

- 基于 `TextPainter`、真实可用视口和当前排版设置计算分页边界。
- 分页结果记录每页起止的段落 ID 与字符偏移。
- 章节标题参与首屏布局，但不改变正文语义锚点。
- 中文正文使用统一首行缩进和段间距规则；不得通过修改源段落文本破坏字符位置。
- 字体、字号、行高、页边距、系统文字缩放或窗口尺寸变化后重新分页。
- 重排后定位包含旧锚点的页面，而不是回到章节开头或旧页码。
- 仿真、覆盖和平移动画只作用于已经分页的页面视觉层，不修改分页边界、源段落文本或持久化位置。
- 系统要求减少动态效果时，所有横向分页动画统一降级为无动画。

纵向模式使用段落级可定位列表：

- 通过段落锚点恢复位置。
- 到达章节底部时可进入下一章，到达顶部时可进入上一章。
- 第一章之前进入书籍信息预览；书籍信息预览视为索引 `-1`，包含标题、作者、简介、章节数量和开始阅读入口。
- 最后一章之后不得停留在空白边界页，必须回到末页并显示“没有下一章”的组件内提示。
- 不把全书所有章节同时挂载到 Widget 树。
- 横向和纵向模式切换时保持同一语义位置。

排版内核应尽量写成纯 Dart/Flutter rendering 逻辑并接受显式输入，便于静态审阅、独立复用和后续维护。

## 9. UI 与交互规范

### 9.1 内置视觉系统

阅读器拥有完整内部视觉系统，宿主不覆盖：

- 七套配色必须同时定义正文、次级文本、分隔线、面板和强调色，并与六套原创阅读背景保持可读对比。
- 六套阅读背景必须由项目原创，可使用程序化渐变、纹理或明确可用的自有素材；不得复制参考截图中的背景图。
- 夜间主题不得仅反转颜色；应控制对比度并避免纯黑纯白长时间刺激。
- 亮度通过阅读区域黑色遮罩实现，不修改设备全局亮度。
- 字体选择必须有跨平台回退链。不要依赖运行时网络下载字体。
- 所有颜色、字号范围、间距和动画时长集中管理，不在 Widget 中散落魔法值。
- 面板、按钮和图标应保持原创、简洁，不复制参考 App 品牌资产。

### 9.2 阅读页结构

正常阅读状态至少包含：

- 章节标题与正文。
- 页码、全书进度和当前时间等低干扰页脚信息。
- 顶部返回、章节信息和书签操作栏。
- 底部上一章/下一章、全书进度、目录/书签、主题和排版入口；进度条不得表示当前章节进度。
- 目录面板：分页加载、当前章高亮、快速跳转、loading/empty/error/retry。
- 书签面板：显示、跳转和删除；新增书签作用于当前语义位置。
- 设置面板：翻页模式与动画、主题、六套背景、字体、字号、行高、页边距、亮度、常亮和会话级自动阅读。
- 注册评论 capability 时提供书籍、章节和段落三级只读评论入口；段评使用紧随最后一个字同行、数量内嵌的紧凑气泡，点击后打开只读列表；未注册时不显示评论设置或占位入口。

工具栏覆盖在固定正文布局上，显示/隐藏工具栏不得改变正文可用尺寸和当前分页。

### 9.3 触摸、鼠标和键盘

横向分页默认交互：

- 左侧约 30% 点击上一页。
- 中间约 40% 点击显示/隐藏工具栏。
- 右侧约 30% 点击下一页。
- 水平滑动翻页；到章节边界时按目录顺序换章。
- 横向分页的拖动设备必须同时包含触摸、触控笔和鼠标，Windows 用户可以按住鼠标直接拖页。

纵向模式中滚动手势优先于点击分区。中心轻点仍可切换工具栏，不能因一次普通滚动误触翻页。

Windows 至少支持：

- 左/右方向键和 PageUp/PageDown 翻页。
- 空格下一页，Shift+空格上一页。
- Escape 发出退出请求。
- 鼠标滚轮在纵向模式滚动，在横向模式按离散阈值翻页。
- 窗口缩放后防抖重排并恢复语义位置。

Android 系统返回键与顶部返回按钮使用同一退出请求路径。

### 9.4 可访问性

- 所有图标按钮提供中文语义标签和 tooltip。
- 正文保持合理的最小字号和触控目标尺寸。
- 工具栏显示后支持键盘焦点遍历。
- 动画遵循系统减少动态效果设置；减少动态时使用无动画分页。
- 重要状态不能只依赖颜色表达。
- 用户可控字号与系统文字缩放需有明确合并和上限策略，防止布局溢出。

首版文案可以只提供简体中文，但所有可见字符串必须集中管理，为后续本地化预留入口；不得在大量 Widget 中散落字符串字面量。

## 10. 生命周期和原生能力

### 10.1 标准生命周期

使用 Flutter 生命周期 API 监听并归一化为：

- `foreground`
- `inactive`
- `background`
- `detached`

重复事件应去重。进入后台时先同步更新内部状态并释放常亮，再异步提交进度；恢复前台后只有仍处于活动阅读会话且设置允许时才重新获取常亮。

### 10.2 屏幕常亮

“禁止黑屏”在本项目中明确指：活动阅读期间阻止系统因空闲自动关闭显示器。它不表示捕获崩溃、覆盖系统锁屏、绕过电源策略或阻止用户主动关屏。

实现规则：

- Android 使用当前 Activity 的 `FLAG_KEEP_SCREEN_ON`，所有窗口操作在主线程执行。
- Windows 使用 `SetThreadExecutionState` 获取和释放显示器执行状态。
- Dart 侧使用引用计数协调多个未来阅读器实例。
- Dart 平台抽象必须声明能力支持情况；不支持常亮的平台忽略已保存设置、不调用平台通道，并从设置面板隐藏常亮选项。
- `acquire`/`release` 必须幂等；引用计数不能小于零。
- 最后一个持有者释放、App 后台、Engine detach 或插件销毁时必须恢复系统默认状态。
- 原生异常转换为可恢复错误，不能让阅读器直接崩溃。
- 平台通道名称、方法名和参数只存在于私有实现，不作为业务公共 API。

Android 与 Windows 原生实现必须保持语义一致。新增原生能力时先扩展可替换的 Dart 平台抽象，再实现各平台，禁止在 Widget 中直接调用 MethodChannel。

## 11. 漫画阅读器契约

漫画阅读器复用：

- 生命周期归一化。
- 常亮资源协调器。
- 会话进入/退出和观察器语义。
- 通用错误类型和异步竞态处理模式。

漫画阅读器不得复用或继承：

- 文本段落模型。
- `TextPainter` 分页结果。
- 文本字号、行高和段间距设置。

漫画使用独立 `Comic*` 模型、数据源、状态存储、Controller、Snapshot、Preferences、Progress 和 Bookmark。只允许纵向连续阅读；章节内容只含稳定图片元数据，`loadImageBytes` 返回完整 `Uint8List`，按视口逐图渐进调度而非流式字节解码。慢图使用稳定占位，局部失败可重试，过期请求不得覆盖新章节；相邻章节无缝衔接，但不得挂载或缓存整本图片。共享 runtime 只能通过组合复用。

## 12. 错误、日志和安全

- 对宿主暴露结构化 `ReaderFailure`，区分数据加载、状态读写、布局、平台能力和未知错误。
- 用户界面显示简洁可行动文案；原始堆栈只用于调试日志和人工诊断。
- 不在日志中输出整章正文、用户标识、鉴权信息或数据库内容。
- 插件不申请网络、存储等与核心能力无关的原生权限。
- 常亮能力不需要通过隐藏权限或后台 Service 实现。
- 对超长文本、空章节、重复/缺失段落 ID、目录顺序异常做可预测处理并报告错误。
- Debug 断言不能代替 Release 下的输入保护。

## 13. Dart 与 Flutter 编码规范

- 使用当前稳定 Flutter/Dart 支持的 null safety 和官方 lint。
- 公共模型默认不可变，提供明确构造器、值比较和必要的 `copyWith`；避免把可变 List 直接暴露出去。
- 所有公共类型和公共成员写 DartDoc，说明生命周期、错误和线程/异步语义。
- 公共命名使用英文；代码注释说明“为什么”，不要翻译代码本身。
- Widget 保持职责单一；复杂面板、状态页和排版逻辑拆分文件。
- 避免巨型 `StatefulWidget`、嵌套三元表达式和无意义 wrapper。
- 不使用 `dynamic` 逃避类型设计，不静默吞掉异常。
- 异步调用后访问 State 前检查挂载状态或使用不依赖 State 的运行时对象。
- Controller、监听器、FocusNode、ScrollController、Timer 和平台资源都必须成对释放。
- 测量、缓存和保存策略中的常量集中定义，通过清晰类型、断言、日志和人工检查保持行为可追踪。
- 格式化遵循 `dart format` 的输出风格；每次实现完成后只运行完整静态语法检查，不运行自动化测试或构建命令。

## 14. 示例应用要求

`example/` 是插件的接入文档和人工验收入口，必须：

- 只使用 `package:novel_reader_ui/novel_reader_ui.dart` 公共入口，不深层导入私有实现。
- 提供至少一本多章节中文演示小说，段落 ID 稳定。
- 使用带短暂延迟的模拟异步数据源，覆盖 loading 状态。
- 提供内存状态存储，演示进度、设置和书签接口。
- 展示宿主如何响应退出请求和生命周期通知。
- 提供可触发的章节加载错误用于验证重试，但默认启动路径必须成功。
- Android 和 Windows 共享同一 Dart 示例代码，不维护两套业务实现。

示例内容必须是原创、公共领域或明确可用的短文本，不复制商业小说内容。

## 16. 人工验收与语法检查

功能变更完成后，Agent 默认停止在代码实现与静态代码审查阶段，由用户运行 `example/` 人工检查。用户明确授权重大视觉改造时，Agent 可以启动 Android 模拟器中的 `example/`，使用人工交互和截图辅助验收；本轮还可在 macOS 做 UI 人工检查，但不验证 Android/Windows 原生能力。推荐但不强制的人工验收重点包括：

不运行 `flutter test`、Gradle 测试、CTest、Golden 更新、Android APK 构建或 Windows 构建。用户明确授权重大视觉改造时允许在 Android 模拟器执行 `flutter run` 和人工交互/截图；本轮还允许 macOS UI 人工验收，但不能声称完成 macOS 平台支持或 Android/Windows 原生验证。Windows 的运行、构建和交互验证只能在 Windows 主机或对应 CI 环境执行。若语法检查或获授权的运行验收因环境缺失无法执行，交付说明必须列出未执行项和原因，不能写成“检查通过”。不要通过降低 lint 或排除源码来制造通过结果。

## 17. 兼容性与版本管理

- 公共 API 遵循语义化版本。删除、重命名、收紧输入或改变默认行为均视为破坏性变更。
- 新增可选能力优先使用带默认行为的可选参数或独立 capability。
- 不把临时实验类型从公共入口导出。
- 原生通道变更必须保证 Dart 与 Android/Windows 同步升级。
- 持久化模型新增字段时提供安全默认值；宿主负责序列化，但插件不得假设旧数据总是完整。
- Flutter 最低版本以 `pubspec.yaml` 为准。提升最低版本必须有明确能力需求和迁移说明。

## 18. Definition of Done

一个阅读器功能只有同时满足以下条件才算完成：

- 符合本文件的产品边界和公共 API 规则。
- Android 行为已实现，并向用户提供真机人工检查入口与关键路径说明。
- Windows 实现已完成；若当前非 Windows 环境，已明确列为待人工检查。
- loading、empty、error、retry、后台和 dispose 路径均被处理。
- 改变排版或窗口尺寸不会丢失语义阅读位置。
- 不存在未释放的 Timer、监听器、Controller 或常亮持有。
- 新增公开 API 有 DartDoc 和示例接入方式。
- Dart 格式与静态分析通过；原生代码已完成静态审阅。
- README 或示例已反映接入方式，不要求宿主阅读内部源码才能正确使用。
