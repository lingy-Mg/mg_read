# 真实网页浏览器探测

## 必须使用的场景

当任务需要确认当前页面结构、选择器、JS 渲染结果、重定向后的页面、分类或分页入口、验证完成后的
DOM，或修复依赖这些事实的数据源解析器时，必须加载 `browser:control-in-app-browser` 并使用 Codex
内置浏览器访问实际网页。不得用 `curl`、Node `fetch`、测试 fixture、搜索结果摘要或静态源码猜测页面
结构。

CLI 网络请求和来源 `test:live` 只用于确认 DNS/TLS、状态码、响应大小、挑战门槛及无需浏览器的稳定
接口；它们不能证明浏览器渲染后的 DOM、交互入口或验证后结构。

## 探测流程

1. 从来源公开 origin、用户给出的 URL 或当前来源规则确定一个具体页面，不通过搜索引擎猜入口。
2. 按 `browser:control-in-app-browser` 选择 Codex 内置浏览器并读取其完整操作文档。
3. 打开真实页面，先记录可见状态、最终地址和是否遇到验证、登录、重定向或错误页。
4. 使用浏览器的页面检查能力核对实际 DOM、可见文本、链接关系、分页和目标选择器；需要视觉证据时
   截图。只读取完成当前解析任务所需的最小页面范围。
5. 将确认过的选择器、缺失字段、分页规则和错误分支写入 fixture 与直接测试。

## 受保护来源边界

- 遇到验证码、Cloudflare 或其他人机挑战时，不自动点击、注入 DOM 事件、提取或回放 token，也不使用
  CDP 绕过。返回明确的 `interaction_required`，由用户在该浏览器中真实完成交互后再继续检查。
- 通过当前可见页面上下文验证登录或验证状态。
- Codex 内置浏览器证据只证明该浏览器中的实际网页结构，不证明 MgRead Windows WebView2 或 Android
  WebView 的 Cookie/Profile、窗口、输入、CORS 或平台行为。三类证据必须分开报告。
- 真实页面暂时不可达时，保留最近已验证的 fixture，明确标记线上结构待复核；不能把旧 fixture 或菜单
  推断写成当前事实。

## 交付证据

报告时分别列出：

- CLI smoke：状态码、挑战门槛和时间；
- Codex 内置浏览器：实际访问的页面类型、最终路由、确认过的 DOM/选择器和截图状态；
- 来源 fixture/测试：哪些规则已固化；
- MgRead WebView：Windows、Android 和未执行项。
