# 来源退役与删除

## 确认精确目标

将用户名称映射到实际来源目录、pluginId 和可能的别名，先去重，再核对是否存在活动注册表、仓库索引、发布
清单、迁移审计或宿主测试引用。历史审计记录与当前可加载注册表不是同一所有者；除非用户要求改写历史，保留
已发生的迁移记录。

## 删除边界

- 只删除确认过的来源目录及其源码、fixture、测试、lock、已跟踪 dist 和来源工具。
- 精确目标目录内的未跟踪 `node_modules`、artifact 或本地构建输出也要清理，否则开发扫描仍可能识别残留来源。
- 只有代码搜索证明存在独立活动注册或发布清单时才同步删除；不要凭猜测修改仓库级配置。
- 不运行已删除来源的测试。验证重点是目录不存在、活动项目枚举不再包含 pluginId、引用清理和其余来源不受影响。
- 删除动作只覆盖用户点名或经语义证据确认的目标；同媒体类型、相似名称或同站点系列不自动进入范围。

## 收尾

核对目标数、实际删除目录数、活动来源总数变化和 staged 路径一致；必要时运行项目发现或全源枚举的只读检查。
最终列出删除项、保留的历史记录、同步修改的活动索引以及未触碰的相邻来源。
