# ADR-0006：插件版本目录与冷激活更新

- 状态：Superseded（被 [ADR-0019](0019-development-plugin-live-loading.md) 取代；installed 插件的冷激活规则继续保留）
- 日期：2026-08-13
- 决策者：MgRead 项目

## 背景

Node ESM 模块会缓存，插件还可能保留闭包、Timer、连接和内部状态。在单 VM 中热替换已加载模块会造成旧/新代码同时存在、内存无法回收、在途请求语义混合，并使回滚难以证明。

## 决策

- 每个插件版本安装到不可变版本目录，禁止覆盖当前目录。
- 下载、摘要、`.mgplugin`/package/lock/SRI 校验、依赖恢复和解压全部完成后才原子提交版本目录与安装记录。
- 已在当前 VM 加载的插件更新只设置 `pendingVersion`，不执行热替换。
- 待更新版本在下次应用进程启动时冷激活。
- 激活前保留 `previousVersion`；新版本首次验证/加载失败时自动回滚，并记录稳定诊断。
- 禁用/卸载已加载插件先逻辑停止分派，实际模块生命周期在进程退出结束。
- 插件更新不触发同一进程 Runtime 重启，避免用“重启 Runtime”绕过单 VM 生命周期约束。

## 后果

正面：

- 一个启动周期内每个插件只有一套代码和模块状态。
- 原子版本目录使失败安装不影响当前版本。
- 回滚只需切换数据库指针并重新启动，证据和诊断明确。
- 避免 query-string 动态 import 等伪热更造成 ESM 缓存和内存泄漏。

代价：

- 用户安装更新后需要完全退出并重新启动应用才能生效。
- UI 必须明确区分“已下载”“待激活”“当前版本”和“可回滚”。
- 至少保留两个版本会增加磁盘占用，需要有界清理策略。
- 激活失败只有下次启动才能被完整发现，启动诊断必须可靠。

## 被拒绝的方案

- **动态 import 新 URL 热替换**：旧模块、闭包、Timer 和缓存仍存活，无法保证状态隔离。
- **清理 `require.cache`**：ESM/闭包/原生资源并不能可靠完全卸载。
- **更新后重启 Node 但不重启应用**：增加同一应用进程的跨 bootId 恢复和双 Runtime 时序风险，首版不接受。
- **覆盖当前版本文件**：崩溃或部分写入会直接破坏可用版本，无法可靠回滚。

## 变更条件

只有存在强产品需求且有可证明的模块隔离/卸载方案时才能提出热激活 ADR。新方案需覆盖在途调用、Timer/连接、缓存、内存释放、失败回滚、资源句柄和三平台生命周期。
