# 01 产品范围与路线图

## 产品目标

MgRead 是以插件为唯一在线数据来源的本地优先阅读应用。首版必须形成“安装插件 → 发现/搜索 → 查看详情和目录 → 加入书架 → 阅读小说或漫画 → 保存进度/书签 → 缓存或下载 → 插件升级与失败恢复”的完整闭环。

首版的性能目标不是先写一个无法验证的毫秒数字，而是保证所有关键路径可测量、可取消、有界、可恢复，并为后续基线比较保留稳定指标。

## 产品原则

1. **插件优先**：真实内容全部来自插件；宿主不内置真实书源。
2. **本地数据优先**：书架、目录快照、正文对象、进度和书签以主应用
   `AppPersistence`/`ContentLibrary` 为权威；Runtime 负责插件执行、在线获取与自己的运行数据，
   不打开主应用数据库。
3. **离线不失效**：插件禁用、损坏或丢失时，本地元数据、进度和已下载内容仍可查看。
4. **首版闭环优先**：音频、视频、账号、同步和 WebView 登录只留下可扩展边界，不交付半成品。
5. **平台行为明确**：Android 优先，Windows/macOS 同属首发承诺；每个平台分别验收和发布。
6. **诚实的高并发**：单 Node VM 支持大量非阻塞 I/O，不把 CPU 并行或同步代码抢占包装成已解决能力。

## 首版用户能力

### 插件管理

- 浏览唯一官方插件仓库。
- 从官方仓库安装，或从本地文件选择器导入 `.mgplugin`。
- 查看插件清单、版本、内容类型、声明能力和诊断状态。
- 启用、禁用、检查更新、下载更新、查看待激活状态。
- 安装或激活失败时保留旧版本并提供明确回滚结果。
- 查看经过脱敏的最近错误和兼容性原因。

### 内容与书架

- 按插件发现内容、搜索、分页加载；内容摘要必须包含稳定 ID、书名、内容类型和显式 nullable
  的作者、URL、封面、简介、字数、章节数、更新时间、最新章节等富字段。
- 查看小说或漫画详情、来源和目录。
- 将内容加入书架；书架项使用 Runtime 稳定 ID，不把 URL 当业务主键。
- 刷新书架元数据和目录，并明确显示来源不可用、认证需要、限流等状态。
- 插件不可用时继续打开已下载内容、进度和书签。

### 阅读与离线

- 通过 `novel_reader_ui` 公开接口进入小说或漫画阅读。
- 保存章节/字符/图片语义锚点，绝不把渲染页码或像素位置当持久化进度。
- 创建、删除和恢复书签。
- 缓存正文/图片并创建可恢复下载任务。
- 应用被系统终止后，下次启动能从持久化检查点继续可恢复任务。

## 首版页面地图

| 页面/界面 | 主要职责 | 关键状态 |
| --- | --- | --- |
| 书架 | 本地内容入口、刷新、离线可用性 | 空、加载、可用、部分来源不可用 |
| 插件中心 | 官方仓库、本地导入、安装与更新 | 未安装、安装中、已启用、禁用、待激活、损坏、可回滚 |
| 发现/搜索 | 按插件浏览和不透明 cursor 分页 | 首屏、翻页、取消、限流、需要交互 |
| 内容详情 | 元数据、来源、加入书架、目录入口 | 在线、快照、来源不可用 |
| 目录 | 稳定章节 ID、缓存/下载状态 | 正常、局部缓存、过期、刷新失败 |
| 小说阅读器 | 公开文本阅读器宿主适配 | 在线、缓存、下载、恢复进度 |
| 漫画阅读器 | 公开漫画阅读器宿主适配 | 图片句柄、Range/缓存、恢复进度 |
| 下载 | 优先级、进度、暂停、恢复、失败 | 排队、准备、传输、暂停、完成、可重试失败 |
| 设置/诊断 | Runtime、协议、插件、缓存与指标 | 未启动、就绪、降级、不可用 |

页面不得直接访问网络、SQLite、文件系统或 Runtime 内部协议。在线来源通过 feature
application 调用版本化 Runtime Facade，本地业务数据通过 feature 窄端口访问主应用
`ContentLibrary`。

## 明确延期

- 账号、登录资料域、云同步和跨设备冲突解决。
- WebView 登录、验证码处理和 Cookie 导入的实际能力。
- 音频/视频播放界面、后台播放、媒体通知和音频焦点。
- 多个官方/第三方仓库、自定义仓库 URL。
- 插件安全沙箱、权限强制、代码签名信任链和本地通信鉴权。
- 插件热更新、多个 Node VM、Worker VM 或进程级插件隔离。
- Google Play、Mac App Store 分发。
- iOS、Linux 和 Web。

`ContentKind` 可从第一版协议包含保留的 `audio`、`video`，但任何首版 UI 或成功响应都不得暗示播放能力已经存在。WebView 和未来媒体 Runtime capability 在首版必须返回标准 `unsupported`。

## 实施里程碑

### M0：架构文档基线

交付本文档集、ADR、开发契约和 README。退出条件：

- 术语只有一个定义位置，专题之间没有相互矛盾。
- WS 两个方向、HTTP 数据面、错误、取消和重连都有完整契约。
- 首版与延期边界可由测试或产品验收观察。
- 所有架构硬约束都有已接受 ADR。
- `mg_read_runtime` 独立运行、Runtime 自有持久化、零主项目注入的边界已由 ADR-0008 固定。
- 可变持久字段采用作用域化版本 JSON，稳定 envelope 与公开强类型投影的边界已由
  ADR-0009 固定；SQLite 分库仍明确标记为等待探针的 Proposed。
- 主应用 persistence/Content Library 的独立验收矩阵已定义，且不依赖 Node、网络或真实书源。
- 不增加运行时代码和依赖。

### M1：独立 Runtime 可行性门禁

只做可丢弃探针，不直接铺业务代码：

- 固定候选 Javet 版本及其精确 Node 24 小版本。
- Android Node 模式、专用线程、事件循环泵送、HTTP/WS、文件系统、ESM、控制台截获、异常回调和关闭行为均有证据。
- Windows/macOS 捆绑 Node 的启动、隐藏窗口、`127.0.0.1:0`、ready、异常退出、HTTP Range 和关闭均有证据。
- 三个平台通过同一协议 fixture；不兼容时先固定版本或维护补丁，不静默更换引擎。
- 无数据库、路径、Cookie、文件、平台 callback 或 `host.*` 从主项目注入时，Runtime 仍可独立启动、恢复并执行固定插件 fixture。

### M2：主项目 UI 基础设施

- Riverpod 组合根与显式可释放状态边界。
- 声明式类型化路由、统一错误模型和诊断入口。
- Runtime Facade 的 UI 消费、强类型投影和阅读器视图接入；不实现 Runtime Client 或持久化。
- 仅为 UI 自身需要建立有界计算与展示状态，不承接插件数据解析、文件恢复或下载。

### M3：Runtime 内核

- Runtime Supervisor、平台承载与启动管道。
- 内部 WS/HTTP、事件、取消、deadline、幂等与重连快照；对主项目只发布 Facade。
- Runtime 自有插件安装树、插件私有 data/cache、Cookie、临时资源与诊断；Range、背压、
  健康探测和句柄生命周期。
- 不在 Runtime 建立书架、目录、进度、书签或正文业务权威；主应用提交/下载跨边界能力需先有
  新的 Accepted ADR 和强类型契约。
- 结构化日志、指标、故障注入入口和零主项目注入验收。

主应用 SQLite/Content Library 的实现与验收由 ADR-0011、ADR-0100 约束。ADR-0010 的 Runtime
SQLite 方案已被取代，不再是后续 Runtime 门禁。

### M4：插件生态

- 标准 Node Plugin API 类型、独立空白模板和假数据插件。
- `.mgplugin`、package/lock/SRI 校验、本地导入、官方仓库、原子安装、冷激活、回滚、启停和诊断。
- Runtime Facade/TypeScript 共享 Schema、fixture 和契约测试；主项目不直接消费 wire protocol。

### M5：小说/漫画闭环

- Runtime 的发现、搜索、详情、目录与受控资源获取；主应用 adapter 将已验证结果提交到
  `ContentLibrary`。
- 主应用完成书架、目录、正文对象、语义进度、书签和离线投影；网络传输、下载 checkpoint 与
  文件提交的跨边界所有权先由新 ADR/契约固定。
- 页面与 `novel_reader_ui` 只消费强类型应用端口和 Runtime Facade，不接触 raw transport。

### M6：首发平台发布

- Android arm64 真机验收和 x86_64 模拟器/CI 冒烟。
- Windows x64 Runtime 独立安装、升级、卸载和 Runtime 捆绑验收。
- macOS arm64/x64 Runtime 分包、Developer ID、Hardened Runtime、公证和升级验收。
- 三个平台的版本兼容、失败诊断和回滚演练。

### M7：后续能力

先单独设计 WebView 登录与 Cookie 交换，再单独设计音频、视频和原生后台媒体服务。每项都必须新增范围文档和必要 ADR，不能从预留枚举直接推导出实现授权。

## 阶段完成定义

每个代码里程碑必须同时满足：

1. 公开契约和迁移路径已记录。
2. 相关分层自动化测试通过。
3. 静态检查通过。
4. 运行、平台或真机验收按实际执行情况分别报告，未执行时明确说明。
5. 没有正文、Cookie、令牌、用户标识或数据库内容进入日志。
6. 性能报告包含可比较基线，不用单次主观感受宣称“高性能”。
