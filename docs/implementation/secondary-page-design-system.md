# MgRead 二级页面与设置空页面规范

## 目的

设置页的每个入口都必须有可到达的二级页面。能力尚未实现时，页面显示明确的“功能建设中”
状态，不用点击后无反馈的临时行为代替路由。能力接入后只替换内容区，不改变顶部和路由层级。

## 页面骨架

二级页面统一使用 `AppSecondaryPageTopBar`；尚未实现的设置项使用
`AppSecondaryPlaceholderPage`。页面规则如下：

- 根部使用 `SafeArea(bottom: false)`，顶部栏必须位于安全区内部，不能把顶部栏放在
  `Scaffold.body` 的裸 `Center` 或 `Column` 中。
- 顶部栏高度为 `AppDetailMetrics.topBarHeight`（64），标题使用 18 号、600 字重并垂直居中。
  返回和右侧操作都使用 48 × 48 命中区。
- 页面内容与主导航页共用 `AppSpacing.contentMaxWidth`（1184）；小于 720 时保留手机布局，
  不额外增加外侧边距，720 及以上使用 `AppSpacing.widePagePadding`（32）并居中。设置二级页的
  底部导航使用 `AppBottomNavigation`，保持“我的”选中态。
- 标题、返回回调和右侧操作是顶部栏的可变参数；页面不得重新定义另一套标题栏尺寸、图标
  命中区或状态栏处理。
- 当前 UI 只验收浅色模式；不新增深色截图或 Golden。

## 返回行为

所有二级、三级路由页面共享同一个返回入口：

- 顶部栏左侧返回按钮调用当前路由的 `pop`。
- 键盘 `Esc` 调用同一个路由返回动作。
- Android 系统返回、Windows/macOS 的系统返回分发到同一个路由返回动作。
- 鼠标侧边返回键使用 Flutter 的 `kBackMouseButton` 分发到同一个路由返回动作。
- 浏览器后退由 `GoRouter` 的浏览器历史接管；路由状态和页面返回层级必须保持一致。

根页面没有可返回的上级时，上述动作保持当前页面，不退出或改变根路由。页面自身若有
`PopScope`、阅读器退出确认或临时弹层，必须先完成自身的返回语义，再交给路由层级返回。

阅读器页面的返回链路另行维护：阅读器内部设置、二级菜单、三级菜单以及异步进度退出会在后续
阶段统一接入逐级返回。本规范本轮只约束普通应用二级、三级路由页面，不提前改变阅读器内部退出逻辑。

## 设置入口与空页面

`ProfileFixtures` 中的设置项使用稳定 ID。尚未接入的设置项通过
`/profile/settings/:settingId` 进入 `ProfileSettingPlaceholderPage`：

| ID | 页面标题 | 当前状态 |
| --- | --- | --- |
| `reading-settings` | 阅读设置 | 空页面 |
| `downloads-cache` | 下载与缓存 | 空页面 |
| `theme-appearance` | 主题与外观 | 空页面 |
| `privacy-permissions` | 隐私与权限 | 空页面 |
| `data-backup` | 数据备份与同步 | 空页面 |

已经具备独立能力的入口继续使用现有路由：数据源管理、清理缓存、关于我们、意见反馈和调试
日志。它们同样必须复用 `AppSecondaryPageTopBar`，不能恢复页面私有顶部栏。

## 三级页面

二级页面继续向下打开的页面也必须使用同一套顶部栏和安全区，不允许在加载态、错误态或空态
移除顶部栏。当前“关于我们”下的五个入口均进入真实三级路由
`/profile/about/:itemId`，数据源管理下的 `plugins/:pluginId` 也属于三级页面：

| 父页面 | 入口 | 当前页面 |
| --- | --- | --- |
| 关于我们 | 检查更新、用户协议、隐私政策、开源许可、联系我们 | 三级空页面 |
| 数据源管理 | 数据源列表项 | 三级数据源详情页 |

三级页面的返回动作只返回父级页面；只有父级不存在时才回到“我的”。子页面的加载、失败和
找不到目标状态必须保留顶部栏，状态内容放在顶部栏以下的内容区域。

## 验收

至少检查：每个缺失入口都能打开二级页面、页面标题和“功能建设中”可见、返回键回到设置页、
顶部栏在带 Android 顶部安全区时不进入状态栏。页面/跨路由流程使用 Android
`integration_test`；组件级尺寸可用浅色 Widget 测试辅助验证，不能把 Golden 作为真实设备验收。
