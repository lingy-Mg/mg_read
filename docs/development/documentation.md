# 文档、规划与 AI 指令维护规则

## 单一入口与最少重复

- 根 `AGENTS.md` 只放所有任务都需要的硬约束和读取算法。
- `docs/development/README.md` 只做任务路由，不复制专题正文。
- 架构结论、跨文件契约和公共流程放架构专题/ADR；阶段计划与证据放
  `docs/planning/README.md` 或拥有它的 package 文档。单个文件的用途、职责、关键协作者、
  IO/状态边界和局部待办写在文件头，不再复制到 README、实现说明或规划中。
- 只有某项细节跨越多个文件、构成公开契约或无法从单个所有者文件表达时才进入 Markdown；文档
  应链接所有者文件或公开符号，不平行维护同一份逐项说明。
- 嵌套 `AGENTS.md` 只写相对根规则的增量。根规则已经覆盖的 Git、安全、日志和证据规则不再
  整段复制。

## 文件头摘要

人工维护文件的头部摘要遵守根 `AGENTS.md` 的全局规则。摘要描述当前事实，不记录作者、日期或
逐次修改历史；Git 负责完整历史，文件头负责让维护者打开文件后立即理解当前所有权和边界。

摘要按文件实际情况使用以下字段：

1. 一句话用途；
2. `职责`：该文件真正拥有的行为；
3. `注意`：不得跨越的边界、关键协作者以及 IO/状态归属；
4. `TODO`：仅保留已经确认但尚未完成的局部事项，没有则省略。

后续任务修改职责、边界、依赖方向、Controller/Service 所有权、IO 行为或 TODO 状态时，代码与
文件头必须一起更新。首次修改尚无摘要的旧文件时补齐；仅格式化、生成物刷新或机械重命名且语义
未变时，只需确认原摘要仍准确。跨文件核心框架也发生变化时，再同步最窄的权威文档，避免把
文件级细节重新抄回专题。

## 文档状态

新增或大改文档时在开头说明它是权威、开发规范、实现说明、证据快照、规划或历史。包含
“当前/已实现/未实现”的说明应写复核日期或可定位的版本/commit，并明确未提交工作区是否计入。

已被 ADR 取代的长文档优先保留原路径并加醒目的历史提示，避免旧链接失效；默认路由不得再
指向它。若旧文件会被自动发现为指令（例如重复 `agent.md`），将其缩成指向唯一入口的兼容
跳转。

## 修改检查

文档任务至少检查：

1. 所有项目 Markdown 的相对链接；排除 vendored Node/npm/toolchain 文档。
2. ADR 索引中的文件名、状态、替代关系和实际文件一致。
3. 根与嵌套 AGENTS 没有相反的测试、平台、数据所有权或 Git 规则。
4. “当前状态”没有把规划、Windows 单平台、源码测试或未提交并发工作写成已发布能力。
5. 任务涉及的人工维护文件头与当前职责、边界和 TODO 一致，文档没有重复这些文件级细节。
6. `git diff --check`、任务文件 diff 和最终 `git status --short`。

移动/重命名会破坏大量引用时，优先更新索引和状态；确需移动时一次性更新全部相对链接并保留
必要的兼容入口。
