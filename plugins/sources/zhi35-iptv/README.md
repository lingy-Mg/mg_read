# IPTV 聚合

MgRead 的 IPTV 视频数据源，保留原 zhi35 IPTV 插件 ID，整合以下公开列表：

| 来源 | 实际列表 | 用途 |
| --- | --- | --- |
| [zhi35/iptv](https://github.com/zhi35/iptv) | `iptv.m3u` | 原有央视、卫视、地方、港澳台和直播中国 |
| [iptv-org/iptv](https://github.com/iptv-org/iptv) | `streams/cn.m3u` | 中国频道备用线路 |
| [YueChan/Live](https://github.com/YueChan/Live) | `GNTV.m3u` | 港台、地方及国际频道补充 |
| [Free-TV/IPTV](https://github.com/Free-TV/IPTV) | `playlist.m3u8` | 国际及部分国内频道 |

不加载 YueChan 的运营商 RTP 组播列表，不混入广播，不根据 EPG 地址编造节目或回看目录。
列表随上游更新；聚合不保证所有地址在所有网络可播。

## 安装与线路切换

在 MgRead「数据源」中导入构建生成的
`artifacts/org.mgread.zhi35-iptv-1.0.3.mgplugin.js`。
插件 ID 仍为 `org.mgread.zhi35-iptv`，显示名为「IPTV 聚合」，原有安装可按同 ID 更新。
独立单文件运行，不需要安装 npm 依赖；桌面主程序也可通过开发数据源目录识别项目。

播放器已支持手动切换分组。播放时打开「选集 / 线路」，选择来源分组后点击「直播」；
报错页的「切换选集」也会打开同一个菜单。仅切换分组标签不会立即打断当前播放。

多线路频道默认提供「自动线路（含直连）」，同时保留所有明确标注来源的手动线路。
自动入口优先最近成功的地址/路由组合，其余 IPv4 优先，每地址尝试默认和直连；
最多八次连接，共十秒、单次四秒。成功路由同时用于 Runtime 媒体代理及其 HLS 子资源，不改变用户代理设置。
HLS 遇到 HTTP 错误、连接失败或无效清单会继续尝试候选。成功只表示清单可用；
FLV/MP4 不预读，媒体分片、解码失败或播放中断不会触发后台自动换线，此时请手动选择。
明确选择的手动线路只解析本身，不会静默改用别的来源。自动入口成功记录仅保留在本次激活内。

## 频道与缓存

同一资源、标准 EPG ID、已核对的央视/CGTN 别名或同地区完整频道名可以合并。
CCTV-5 与 CCTV-5+、CCTV-4 亚洲/欧洲/美洲、独立 4K 频道和不同国家同名频道分别保留；
「新闻综合」等通用名称不跨地址合并。无法确认相同的频道保持独立。

已有 zhi35 频道优先保留旧 ID，并接受合并前的频道标识。
新增频道沿用上游 EPG/资源摘要，不以显示名作内容主键；线路 ID 排除临时授权参数，实际播放地址保留完整参数。
相同资源去重后汇总来源标签，分组 ID 不依赖线路排序。上游移除或彻底更换资源身份仍可能产生新 ID。

四个来源分别缓存五分钟，并行加载、刷新单飞；单个来源失败不影响其余来源。
失败可用各自 24 小时内的快照，不延长有效期；普通浏览失败后间隔一分钟重试，显式刷新可立即重试。
降级状态会显示在频道列表提示中。每表至多 3 MiB，单请求八秒，同仓库备用地址依次回退。
播放重新获取列表以更新授权，不读取主应用数据库，不保存直播主体。手动线路遵循现有代理设置。

HLS 播放前最多检查 8 KiB 清单；无扩展名入口最多取 1 KiB 识别容器并立即取消。
401/403/451 使用公开来源访问错误，其余失败使用来源媒体解析错误。
消息保留频道名和 HTTP 状态，不暴露地址、授权查询、headers 或响应主体。
部分线路需要 IPv6，是否可访问取决于实际网络和上游限制。

## 台标

发现、分类、搜索和详情共用台标处理，优先保留原频道已声明的台标。
`live.fanmingming.cn/com/tv/` 转同一官方 GitHub 原图，已核实的失效镜像仅解包至对应原仓库。
中天娱乐 `CTI3.pngg` 修正为实际存在的 `CTI3.png`。
地方台先 HEAD 保留正常原址；确认 404/410/HTML 后，只在已有提供方的公开目录精确匹配同名文件。
缺图输出空台标并保留频道，传输失败不判成缺图；不生成或模糊猜测台标。
HEAD 四路限流、缓存与取消有界，图片和媒体主体由 Runtime 转发。

## 开发与验证

使用仓库固定 Node 26.10.0 / npm 11.19.1。在本目录执行：

```powershell
$nodeDirectory = (Resolve-Path '../../../packages/mg_read_node_runtime/tools/node-v26.10.0-win-x64').Path
$env:Path = "$nodeDirectory;$env:Path"
& "$nodeDirectory/node.exe" "$nodeDirectory/node_modules/npm/bin/npm-cli.js" run verify
& "$nodeDirectory/node.exe" "$nodeDirectory/node_modules/npm/bin/npm-cli.js" run test:live
& "$nodeDirectory/node.exe" "$nodeDirectory/node_modules/npm/bin/npm-cli.js" run test:logos
```

`verify` 包含类型检查、离线身份/缓存/选线回归、Runtime 校验和确定性/隔离加载/哈希及单文件打包。
`test:live` 遍历全部分类与分页，按分类抽样目录、封面和线路，内容解析四路限流且最多 48 个样本，
媒体前缀探测最多 24 个；未测项和失败均保留在忽略目录 `artifacts/live-report.json`。
`test:logos` 检查所有已登记台标及各表面，不把缺图或未登记表面视为通过。

2026-11-05，1.0.3 的 35 项离线测试与打包通过；播放器已有的 15 项切换/重试等相关测试通过。
真实四表聚合得到 2,735 个频道、3,035 条线路。CCTV1 保留原 ID，合并为四条地址，另有自动入口。
全分类遍历与搜索、详情、目录通过，封面抽样通过；48 个内容/媒体样本中 20 个通过、28 个失败，另有未测样本，整体为 `partial`。
CCTV1 自动入口选到直连地址并通过 HLS 清单及分片检查；四条手动默认路由本次未通过。

Node 快速检查仍因手动备用地址失败而停止。开发中曾以 Windows Release 0.14.8+497 实际检查 1.0.3：
识别、发现、搜索、详情、目录和 `content.first` 通过，`content.middle` 失败，未进入 `playback.video`。
随后人工实播发现，当时可达的一条 CCTV1 标签地址实际播放“花垣综合”；当前包已按稳定资源摘要排除其错误归属，
不屏蔽该主机其他资源，也不擅自改名。最终包改为显式含直连的自动入口并完成上述 Node 验证。
界面操作被 Esc 中止后未继续；正确 CCTV1 节目画面、最终包的播放器首帧/进度和人工切线尚未验收，Android 未执行。
可达清单或分片不能证明频道标签正确，亦不能宣称全部线路可播。
