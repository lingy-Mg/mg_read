# IPTV 聚合增量规则

- 保留 `org.mgread.zhi35-iptv` 身份，显式消费 zhi35/iptv 的 `iptv.m3u`、iptv-org/iptv 的 `streams/cn.m3u`、
  YueChan/Live 的 `GNTV.m3u` 和 Free-TV/IPTV 的 `playlist.m3u8`；入口集中在 `src/store.mts`。
  不重复加载 live-china、不混入广播，不读取运营商 RTP 组播列表或生成 EPG 回看。
- 频道聚合集中在 `src/merge.mts`：仅共享资源、标准 EPG、核对的央视/CGTN 别名和同地区完整名称可合并。
  CCTV5/5+、CCTV4 地区版、独立 4K、不同国家同名台和通用频道名保持边界；标题只用于匹配，不作内容主键。
  原 zhi35 身份优先，保留旧标识与检索别名；线路按稳定资源去重并保留提供方，真实 URL 授权参数不裁剪。
  实播已确认的错标只按具体资源摘要排除错误归属，不屏蔽同主机其他资源或猜测改名。
- 四表独立五分钟缓存、并行加载、整批单飞；失败可读各自 24 小时内快照且不延长 TTL，普通失败一分钟后重试。
  每请求八秒、每表最多 3 MiB；部分失败显示真实降级提示，全部无有效快照才失败。activate 重建所有缓存。
- 现有播放器通过 groups 手动选线；每条地址一个明确来源标签的分组，多线路另提供稳定自动入口。
  `src/playback.mts` 仅做打开前选择，自动入口明示“含直连”，最近成功/IPv4 优先，每地址默认/直连各一次，
  共八次、十秒、单次四秒；成功路由必须传给 Runtime 资源描述。不得改变用户代理设置。
  明确选择的线路不得静默回退；不监控媒体主体或承诺播放中自动换线。
- HLS 播放前最多读取 8 KiB 清单元数据，检查 HTTP 状态和标记；FLV/MP4 不预读，主体由 Runtime 转发。
  401/403/451 使用 `source_access_blocked`，其余失败使用 `source_media_resolution_failed`；最终自动失败使用后者。
  消息/日志不包含地址、授权查询、headers 或响应主体。
- 台标策略集中在 `src/logos.mts`，各表面共用；优先保留原图身份，镜像仅转对应 GitHub 原图。
  地方台 HEAD 确认缺失后只查既有目录精确同名回退，否则输出 null 并保留频道；不猜图，不把传输失败当缺图。
- `verify` 覆盖聚合边界、缓存降级、自动/明确选线和公开契约；`test:live` 全分类遍历与有界媒体抽样，
  `test:logos` 全量已登记图片检查。网络失败和未测项保留 artifacts 报告，不静默过滤失效线路或宣称全源可播。
